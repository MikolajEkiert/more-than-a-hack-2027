- 2026-11-13 · setup · The local PR job now also fixes review findings and merges: fix commits are pushed to the PR branch only after `make check` passes, and a PR is merged when the review verdict is "looks good" and `make check` passes on main + PR. No human approval step; label `no-auto` opts a PR out. The job rewrites the PR branch (adds fix commits, and merges main into it); pull before continuing on it. The fixer may not edit the gate itself (`scripts/`, `Makefile`, `pyproject.toml`, `AGENTS.md`, `.claude/`...), and a PR that touches organiser code or data (`evaluation/`, `starter/`, `data/`, `submission/`) is never merged automatically (narrowed from an earlier list that also held `.github/` and the manifest; see the next line). `check_repo.py` also fails when the manifest differs from origin/main unless `ALLOW_MANIFEST_CHANGE=1`. Chosen for speed with four days left; GitHub Actions cannot gate (billing lock).
- 2026-11-13 · setup · The PR job always ends in a merge: findings the fixer leaves to the team are deferred (listed in a follow-up comment), not blocking, and after three fix rounds a PR with only `needs changes` findings is merged anyway. A human is asked only for a `blocking` verdict (hard rules, AGENTS.md section 2) and for PRs that change organiser code or data. Chosen by the repo owner so that nothing waits on a person.
- 2026-11-13 · task 01 · Baseline equivalence verified on the data: `tests/test_baseline_equivalence.py` passes (the pipeline reproduces `baseline_smooth50.csv`), public sanity 0.3256 as in EVALUATION.md.
- 2026-11-13 · task 01 · The ATD ball speed column (`Match.ball[:, 2]`) is not used by any new method. It is filled on 7,377 of 94,214 tracked graded frames and its values disagree with the positions (median 1.3 m/s against 5.1 m/s from positions). Ball speed, acceleration and heading change come from `features.ball_kinematics` (quadratic Savitzky-Golay over 7 frames). The player speed column agrees with positions (correlation 0.92) and is used as is.
- 2026-11-13 · task 01 · Ball gaps are all-or-nothing on this tracking: 17 gaps under 1 s, none between 1 and 3 s, 133 of 3 s or more covering 40.7% of graded frames. So there are no short occlusions to bridge and no use for `X`; the question is which long gap is a stoppage and which is play with the ball lost. Gap length does not separate them; the players' speed inside the gap does better (median of the 90th percentile: bulk 1.0-2.0 m/s, tail to 6 m/s, against a play mode near 3-3.5 m/s). This replaces the gap-length mixture proposed in docs/research/UNSUPERVISED_RESEARCH.md section 4.1.
- 2026-11-13 · task 02 · Versions are chosen on another match, never on the public window: `possession validate` scores a config on Metrica's public Sample Game 3 (same provider and format), with labels derived by an algorithm from its corrected tracking and events, and with the tracking degraded to resemble ours (59.5% ball tracked, 131 long gaps covering 40%, 20.7 players visible, against 59.3%, 133, 40.7% and 20.5 on our data). The signal passes the test the full match sets: baseline window 50 scores 0.318 [0.292, 0.347], 125 scores 0.297, 25 scores 0.272, the same order as EVALUATION.md reports. Runs: `experiments/runs/20261113T214811_*`. Limits are in docs/ARCHITECTURE.md.
- 2026-11-13 · task 02 · Considered and not used for validation: DFL/IDSSE (its possession flag flips on single touches, a different convention from the provider's; see docs/research/UNSUPERVISED_RESEARCH.md section 8) and Smart Tagging agreement (tags are fixed 35 s windows, and only 23% of the long ball gaps have a set-piece tag within 5 s of their end).
